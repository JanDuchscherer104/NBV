Problem being solved

Too many truth surfaces, too little routing evidence

Before

  • Skills risked becoming mini-docs, mini-thesis pages, or mini-backlogs.
  • Context7 and MCP tool usage depended on agent memory instead of explicit routing handles.
  • Literature links were discoverable, but not horizontally connected to domain skill activation.
  • Fixture checks protected skill owners, but not tool over-trigger or under-trigger behavior.

After

  • Skills point to owners through compact metadata, not duplicated project truth.
  • Context7 IDs live in one curated file and can be statically validated.
  • Literature routing labels connect skills to Quarto pages, BibTeX keys, and local TeX mirrors.
  • Fixtures can assert required or forbidden MCP tool edges for a task shape.

The owner surface decides what is true. The evidence refs decide what to inspect next. That separation is the core anti-drift move.

Source ownership

The new metadata is deliberately thin

Metadata key Purpose Validation
context7_refs Exact external library doc IDs for tasks where API behavior matters. Must exist in .agents/references/context7_library_ids.md.
literature_refs BibTeX keys, local literature paths, or context-map route labels. Must resolve to references.bib, repo paths, or context-map routes.
tool_refs Canonical MCP tool handles that a skill may need. Must use mcp__<server>.<tool>; unknown canonical refs warn.
Audit hardening

scripts/scaffold_audit.py now owns the gate

Static schema

  • Known metadata keys are enforced.
  • Unsupported values still fail for skill modes and canonical sources.
  • Generated literature indexes are rejected as metadata owners.

Tool registry

  • MCP_DOCKER browser, Python, Context7, and paper tools are enumerated.
  • code-index and OpenAI developer docs tools are included.
  • Unknown but well-formed refs warn instead of silently passing as known.
