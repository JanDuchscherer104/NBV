Scope of the E2E claim

Rollout selection is exact after deterministic tie-breaking: all 20 selected rows and shell indices match. The selected pose matrices still differ by at most 4.77e−7, and raster visibility is discontinuous at silhouette edges; 1,151,982 of 1,152,000 depth values remain within float16 storage tolerance, while 18 edge pixels do not and 12 valid-mask pixels differ. This is distinct from an identical-input kernel failure: the direct Mojo↔CUDA raster fixture passes, and the matching-pose VIN renderer check passes with 1.76e−5 maximum depth error and exact masks. VIN RRI is within the 1e−3 derived-score threshold but not strict 1e−5 identity. Whole-store identity is also not claimed for EFM3D backbone and detection fields because its upstream free-space sampler remains stochastic across CPU and CUDA.

Contract and interpretation

Forward-only Mojo surface

The Python-importable pytorch3d._mojo module is compiled from genuine Mojo sources: pytorch3d/csrc/mojo/_mojo.mojo, pytorch3d/csrc/point_mesh/point_mesh_mojo.mojo, and pytorch3d/csrc/rasterize_meshes/rasterize_meshes_mojo.mojo. They implement point-to-face distance forward, face-to-point distance forward, and the restricted mesh-rasterizer forward used by ARIA-NBV; no ARIA-specific C++ or header bridge is involved. Autograd paths remain on the upstream PyTorch3D _C implementation, and Mojo is not selected for gradient-bearing calls.

One switch

PYTORCH3D_BACKEND=auto|cpu|cuda|mojo controls both strict operator dispatch and ARIA geometry-device selection.

What parity means

The operator gate uses the same fixture and fork commit, exact shape/integer outputs, and rtol=2e-5, atol=2e-6. The real-store audit requires exact structure, dtypes, non-floats and finite masks, with stage thresholds of 1e-5 for rigid transforms and 1e-3 for rendered depth and derived scores.

Dispatch is contained in the PyTorch3D fork. ARIA-NBV chooses the matching geometry device, while pose generation, rendering, VIN writing, and rollout generation continue through the normal PyTorch3D API.

Install and verify on Apple silicon

Prerequisites: macOS 15+, Xcode 16+, and arm64 Python 3.11.

cd aria_nbv
export UV_PROJECT_ENVIRONMENT="$HOME/.cache/aria-nbv/venv"
uv sync --locked
PYTORCH3D_BACKEND=mojo uv run --locked python -c \
  'from pytorch3d import _mojo_ops; assert _mojo_ops.has_mojo()'

Generate data

PYTORCH3D_BACKEND=mojo uv run --locked nbv-build-offline \
  --config-path ../.configs/build_vin_offline_81286_backend_smoke.toml
PYTORCH3D_BACKEND=mojo uv run --locked nbv-build-rollouts \
  --config-path ../.configs/build_rollouts_v1_smoke.toml

Use PYTORCH3D_BACKEND=cuda for the same commands on a CUDA host. Strict mojo and cuda modes reject unsupported contracts instead of silently changing backend; auto may use the matching upstream fallback.
