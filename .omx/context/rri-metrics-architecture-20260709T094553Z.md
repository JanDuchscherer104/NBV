## Task Statement

Plan a better module architecture for `aria_nbv/aria_nbv/rri_metrics` after
the recent clean-rename hierarchy refactor. The user is unhappy with the
current nesting and public surfaces and wants a RALPLAN-style consensus plan
grounded in `make context-heavy` artifacts, `improve-codebase-architecture`,
and `python-docstrings` guidance.

## Desired Outcome

- Reduce shallow one-file folders and excessive `__all__` surfaces.
- Make the core RRI/rollout/Q_H metric seam obvious.
- Separate differentiable objective-like tensor functions from diagnostic
  sanity checks.
- Decide where DTOs/dataclasses should live and how they stay linked to their
  producer functions.
- Require typed/documented TorchMetric state attributes.
- Preserve behavior; this is a package architecture plan, not a semantic
  metric change or Q_H implementation.
