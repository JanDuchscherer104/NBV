Module ownership map for oracle supervision, metrics, rollouts, and data handling

The central fix is to stop sharing ownership of the same scientific concept. Metrics own formulas. Oracle owns evidence and labels. Rollouts own replay and storage. Data handling owns source data and target source rows.

data_handling = source/cache/targets oracle = evidence/scorers/pipelines metrics = formulas/objectives/reducers rollouts = replay/storage/inspection pipelines = historical shell
Current codebase

Architectural status: BLOCK

`rollouts` still owns target scoring, generation orchestration, replay storage, and read-side inspection. `rri_metrics` still exports oracle scoring.

Corrected plan

Formula conflict resolved

No `oracle.rewards` formula owner. Root/log/endpoint gains and selected returns belong to metrics.

Implementation gate

Reduced LOC required

The final PR must remove wrappers, broad barrels, duplicate helpers, and old public paths rather than only shuffling files.

One Rule

Metric formulas live in metrics. Oracle code prepares evidence and emits labels by calling those formulas. Rollouts replay and store generated evidence. Data handling owns source data, target rows, target selection, and offline caches.

DTO Ownership

Producer-local by default

A DTO should live beside the code that produces it unless several independent producers share it.

  • DistanceBreakdown in metrics.point_mesh
  • RriResult in metrics.rri
  • Root/eval point clouds in oracle.evidence
  • Pipeline run summaries beside the pipeline

Shared only when truly shared

Do not keep expanding a package-wide types.py because it hides producer ownership and makes import cycles harder to reason about.

  • Target source rows in data_handling.targets.types
  • Oracle label rows in oracle.labels
  • Replay rows in rollouts.trace or rollouts.zarr_store
  • TorchMetric states as typed attributes on classes

Workpackage Order

WP0 - Contract lock and baseline

Add stale-import scans, formula parity tests, scorer parity tests, and baseline LOC counts before moving files.

WP1 - Metrics formula de-duplication

Create the metrics-owned gains/returns seam. Move core differentiable reductions away from diagnostics. Make TorchMetric states typed and documented.

WP2 - Create the oracle scoring boundary

Move evidence, scene RRI, target RRI, target crop policy, and label DTOs under aria_nbv.oracle. Oracle calls metrics formulas.

WP3 - Move generation pipelines under oracle

Move scene labeler, rollout dataset writer, shards, and CLI under oracle.pipelines. Keep command names stable.

WP4 - Narrow rollouts to replay/storage

Remove scorer and writer exports, keep transitions, trace, Zarr store, inspection, and store-status CLI.

WP5 - Split data_handling internals later

Keep data handling as source owner now. Split _target_selection.py into targets/ after oracle extraction unless cycles force it sooner.

WP6 - Move app pure helpers after domain owners exist

Streamlit pages should consume oracle pipeline/read models and rollout inspection summaries, not construct domain workflows.

WP7 - Off-axis pruning

Archive active rl/ and interpretability/ in a separate PR because app and tests still import them.
