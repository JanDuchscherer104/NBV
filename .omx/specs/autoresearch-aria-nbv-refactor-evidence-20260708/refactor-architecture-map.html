Target Ownership Rule

The stable architecture is not "move everything into one place." It is a four-owner split: finite candidate tables in pose_generation, Oracle RRI orchestration in pipelines, pure metric math in rri_metrics, and replay/store/read contracts in rollouts.

pose_generation

Generate and validate finite candidate tables, orientations, and provenance.

pipelines

Own render, backproject, scene/target eval-region policy, scorer configs, and labeler lifecycle.

rri_metrics

Keep OracleRRI.score, CORAL, bins, and pure metric DTOs free of orchestration.

rollouts

Own selected-transition replay, trace DTOs, zarr stores, shards, and dataset writer plumbing.

app / rerun

Consume typed read models and diagnostics; keep UI glue thin.

Oracle RRI Scatter: Current vs Target

Current scatter

  • pipelines/oracle_rri_labeler.py: one-step scene labeler.
  • pose_generation/counterfactuals.py: scene rollout scorer and replay contracts in the main checkout.
  • pose_generation/target_counterfactuals.py: target rollout scorer, GT OBB crop, target/scene RRI payloads.
  • PR15 cleanup worktree moves those counterfactual files to rollouts, but that is only an intermediate boundary repair.

Target consolidation

  • pipelines/rollout_oracle_rri.py: unified scene and target rollout RRI scorer skeleton.
  • pipelines/oracle_rri_regions.py: scene extent vs GT-OBB target policy.
  • rri_metrics/oracle_rri.py: unchanged primitive metric owner.
  • rollouts/dataset_writer.py: consumes pipeline scorer; it does not own scoring semantics.
