2. Move Rollout Data Generation into Pipelines

Strong in-process

Files: rollouts/{dataset_writer,shards,shard_manifest,cli}.py, pipelines/oracle_rri_labeler.py

Before
pipelines: single-step labeler
rollouts: writer + shards + CLI
rollouts: replay + Zarr + inspection
After
pipelines.rollout_generation: writer + shards + CLI
rollouts: replay + Zarr + inspection
rri_metrics.oracle: label scorers

Problem. Generation orchestration lives in the replay package.

Solution. Pipelines own the writer, shard campaign, and CLI implementation.

  • locality: jobs live together
  • leverage: stable command seam
  • interface: rollouts shrink

  • interface: diagnostics named

Top recommendation

Start with Oracle Rollout Scorers, then Pipeline Ownership

Move scene and target RRI scorer semantics into `rri_metrics.oracle` first, because that is the scientific interface. Then move writer/shard/CLI orchestration into `pipelines.rollout_generation`, and only then finish the narrower `rri_metrics` cleanup.
