# Bounded professor–student iteration

Freeze one figure family, exact scientific owner/ref, incoming reader state,
misconception, one takeaway and intended physical dimensions. Keep baseline
source and color/grayscale renders outside tracked paths. Label an unused old
figure as historical rather than inferring that it is part of the current thesis.

1. **Author:** write the scientific graph before optimizing layout.
2. **Student:** cold-read the artifact; report the first interpretive failure.
3. **Professor:** trace information, equations and assumptions against the owner.
4. **Illustrator:** change one diagnosed cause: topology, wording, font hierarchy,
   box width, padding, line breaks, rank direction or figure split.
5. **Validator:** run exact notation checks, render, measure effective type and
   bounds, then inspect color/grayscale at the intended size.

Record the tested hypothesis and before/after evidence. Three substantive
iterations is a useful default budget, not an obligation. Stop when the lesson
and gates are satisfied. If repeated changes only trade one illegibility for
another, split the view or change renderer. Never “improve” a score by deleting
scientifically essential dependencies or lowering the readability floor.

## Mermaid Chart

Discover the official tool actions available in the current environment. Use
`display_mermaid(diagramCode=..., title=...)` for preview; preserve `documentID`
when updating a saved diagram. Copy accepted changes back to the `.mmd` owner.
The current action returns an interactive browser widget; it is not a server
validation receipt and does not return an inspectable SVG. A tool response is
not evidence that a reviewer saw a successful render. Hosted font availability,
CSS sanitization and math support can differ from local CLI and GitHub fences.

Use the local wrapper or hosted exact-head CI for reproducible renders. State
which artifacts were actually inspected. Do not claim CMU Serif from a CSS
string: check installed faces and actual browser fonts. Do not send private
source to an external preview tool without authorization; these project examples
are public repository material.

## Autoresearch integration

Use an available autoresearch harness as orchestration only. Its packet holds
source SHA, owner/ref, lesson, hypothesis, baseline/candidate renders, measured
sizes, professor/student critiques and disposition. Keep its existing state
schema; do not create a second project tracker. Without the harness, run the
same bounded loop directly and honestly call it a self-review, not independent
agent approval. Publish only accepted source changes within user authorization.
