The Goal That Produced the Monster

The accepted scaffold plan began with a coherent target: replace a layered, stale, duplicated agent scaffold with a smaller source-owned system. During execution, that target absorbed several independent projects and conflicting success criteria.

Initial problem
Too many skills, stale generated context, unclear truth ownership, and overlapping Graphify/LitKG routes.
→
Expanded architecture
Tracked OMX lifecycle, unified graph, skill allowlists, LitKG retirement, state-journal retirement, thesis ownership, and debrief migration.
→
Late additions
Typst equation repair, QMD-to-Typst consolidation, source-link macros, glossary prune audit, and cross-modal Graphify bridges.
Durable objective

Simple routing, progressive disclosure, source-owned truth, small prompt footprint, and exact-source verification.

Category error

A single PR was asked to prove both aggressive deletion and complete preservation, both upstream-minimal Graphify and custom cross-modal parsing, and both thesis consolidation and public-doc removal.

Does Graphify Work and Is It Useful?

Answer: useful as an exact relationship browser, not yet proven as the default agent navigation layer.

The current integration succeeds when the agent already knows a symbol or file label. It is noisy for broad natural-language discovery, and its custom adapter is larger than the implementation it replaces.

What differs from canonical upstream behavior

Upstream Graphify

  • Builds code structurally and docs semantically.
  • Produces graph.html, GRAPH_REPORT.md, and graph.json.
  • Owns query, path, explain, clustering, reports, and visualization.
  • Can install native assistant guidance and hooks.

PR #30 adapter

  • Selects exactly code, Typst thesis, and manifest-selected TeX.
  • Converts non-Python documents into synthetic Python before code-only extraction.
  • Rewrites every node and edge back to exact source locations.
  • Runs clustering without labels or visualization and discards the native report.
Why there is no GRAPH_REPORT.html

Upstream does not define that filename. Its normal outputs are graph.html, GRAPH_REPORT.md, and graph.json. PR #30 intentionally invokes clustering with --no-label --no-viz and then retains only graph.json and a custom manifest.json, so both the native HTML visualization and Markdown report disappear. Native graphify tree can still generate a separate local hierarchy HTML on demand.

Recommended Graphify decision

Keep the experiment, not the integration contract.

Use the branch's adapter as a benchmark candidate. Before merging any replacement, compare it against plain upstream Graphify and exact-source tools on 10 representative agent tasks. Merge only if it materially improves owner discovery or cross-modal traceability without requiring more than a thin repository boundary.

How to Make the Work Manageable

Do not rebase or squash PR #30 into a smaller-looking commit.

A squash hides history but leaves the same 383-file review problem. Start new branches from current main and reconstruct only approved outcomes.

Immediate actions

Archive PR #30

Close without merge. Add a final comment linking this report and label the branch as experimental evidence. Do not delete the branch until salvage work finishes.

Restore review baseline

Use current main as the only base. Do not cherry-pick broad scaffold commits. Copy narrow hunks manually or cherry-pick only after inspecting their complete dependency surface.

Freeze destructive removals

No skill, Quarto page, LitKG route, state journal, or context helper is removed until its own replacement PR demonstrates parity.

Restore lost contracts first

Before salvaging new work, restore or explicitly resolve RQ5, the missing advisor decisions, unresolved glossary citations, and the stale tracked PDF. These are blockers, not optional cleanup.

Review rules for every replacement PR

One purpose

The title, body, diff, and tests describe the same behavior.

One owner

Every moved fact names its old and new authoritative surface.

One proof

A small executable test or fixed evidence matrix proves the claimed improvement.

No binary churn

Generated PDFs, graph outputs, and caches stay out unless they are the explicit deliverable.

No shadow deletion

Capability removals are listed in the PR body and tested, not buried in consolidation.

Green hosted CI

Local evidence is not enough. The exact head must pass GitHub checks.
